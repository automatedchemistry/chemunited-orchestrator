# chemunited-sim

`chemunited-sim` is a dynamic simulation engine for fluidic automation
platforms described with `chemunited-core` components and connections.

The package compiles a ChemUnited platform into a flat hydraulic graph, solves
steady-state pressures and flows, moves liquid/gas pockets through transport
edges, updates vessel inventories, applies simple reaction models, and records
simulation state to SQLite.

It also ships a self-contained **simulation server**: a long-running FastAPI
process that loads a project at runtime, runs it at CPU speed (mode 1 —
workflow simulation) or wall-clock pace (mode 2 — real-time shadow), and
exposes results as a WAL-mode SQLite database that a GUI can read live.

## Install

From the repository root:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
```

For development tools:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

`chemunited-core` and `chemunited-workflow` are installed directly from GitHub
through `pyproject.toml`.

## Simulation server

```powershell
chemunited-sim [project] [--port 1472] [--db ./simulations/] [--with-mcp]
```

Starts a FastAPI server at `http://localhost:<port>`.  OpenAPI docs at
`http://localhost:<port>/docs`.

| Argument | Default | Description |
|---|---|---|
| `project` | — | Path to a project folder or `.chemunited` ZIP. Omit to start in `NO_PROJECT` state. |
| `--port` | `1472` | Listening port |
| `--db` | `./simulations/` | Directory where `.db` files are written |
| `--with-mcp` | off | Mount an MCP endpoint at `/mcp` on the same host/port — see [docs/mcp-tools.md](docs/mcp-tools.md) |

### REST API

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/project/load` | Load or replace a project; compile its hydraulic graph |
| `GET` | `/project` | Info about the currently loaded project |
| `GET` | `/status` | Server state: `sim_status`, `current_t`, active `SimConfig` |
| `POST` | `/simulation/start` | Start a simulation run (`execution_id`, `dt`, `t_end`, `real_time`) |
| `POST` | `/simulation/stop` | Abort the running simulation |
| `POST` | `/simulation/command` | Enqueue a component command (mode 2 only) |
| `GET` | `/simulation/db` | Path of the active or last `.db` file |
| `GET` | `/simulation/visualization` | Interactive pyvis graph for the latest recorded snapshot |

Open `http://127.0.0.1:1472/simulation/visualization` in a browser to inspect
the latest available simulation snapshot.

### MCP server

Pass `--with-mcp` to also mount a streamable-HTTP MCP endpoint at `/mcp` on
the same host/port, so an LLM agent can load a project, run a simulation, and
pull back structured pressure/temperature/flow/content results to judge
whether a process is feasible — without needing the REST API or the raw
`.db` file. No authentication (local-only, matching the REST API's
`127.0.0.1` default). See [docs/mcp-tools.md](docs/mcp-tools.md) for the full
tool reference.

### Server state machine

```
NO_PROJECT ── POST /project/load ──► IDLE
    IDLE    ── POST /project/load ──► IDLE   (replaces project)
    IDLE    ── POST /simulation/start ► RUNNING
    RUNNING ── POST /simulation/stop ─► IDLE
    RUNNING ── auto-complete ─────────► IDLE
    RUNNING ── POST /project/load ────► 409  (rejected)
```

### Mode 1 — Workflow simulation (`real_time=False`)

The protocol runs in-process via a `SimClient` that busy-waits on `SimClock`
instead of `time.sleep()`.  Commands generated by the protocol are enqueued and
applied by the Worker Thread between physics steps.  The simulation runs at CPU
speed — far faster than real time.

### Mode 2 — Real-time simulation (`real_time=True`)

No workflow thread is spawned.  The Worker Thread runs at wall-clock pace.
Commands arrive at `POST /simulation/command` from the work-server as it
executes them on real hardware.

## Programmatic usage

```python
from chemunited_sim.adapter import compile_graph
from chemunited_sim.worker import SimConfig, Worker

graph = compile_graph(components, edges)
worker = Worker(graph, components, SimConfig(dt=0.1, t_end=10.0))
worker.run()

print(worker.t)
print(worker.hyd_state.pressures)
print(worker.hyd_state.flows)
```

See [docs/quickstart.md](docs/quickstart.md) for a complete runnable example.
